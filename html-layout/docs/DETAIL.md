# HTML 布局编辑器

在右侧栏里打开一个工作区中的 HTML 文件，直接拖动页面顶层区块调整顺序，然后把这份「布局意图」交给 agent，由它改写真正的 HTML/CSS。

## 为什么不是所见即所得

拖拽只产出**意图**（区块的顺序与定位信息），不写文件、不注入 inline style。代码始终由 agent 用正常的文件工具改写，所以最终落地的是一份干净、可维护的源码，而不是一堆只能看不能改的临时样式。

## 使用

入口有两个：

- 会话头部右上角的操作区：三层横条图标，点一下展开布局编辑器标签；再点只是聚焦已有标签。
- 右侧栏的工具页（标签条上的 `+`）：**更多工具** 菜单里有一行 **布局编辑器**。

步骤：

1. 在顶部输入工作区内的 HTML 路径，例如 `demo/index.html`，点 **加载**。
2. 预览里每个顶层区块左上角会出现编号手柄，拖动它调整顺序，蓝色横线是插入位置。按 `Esc`、或把指针拖出预览窗口再松开，都会取消这次拖动。
3. 底部显示区块数与改动数；点 **恢复顺序** 撤销全部拖动，或点 **让 agent 改代码**。
4. 这份顺序会作为一条用户消息发给当前会话的 agent，agent 随即改写该文件的结构与 CSS，并说明改了哪些文件。
5. 文件被改写在磁盘上之后，面板提示「文件已在磁盘上改变」，点 **重新加载** 看新结果；如果你还有没发送的拖动，加载前会先确认。

## 预览做了什么

- 以 `sandbox="allow-scripts"`（无同源权限）的 iframe 渲染页面，页面拿不到 Harness 的 DOM、Cookie 或存储；`referrerPolicy` 为 `no-referrer`。
- 页面引用的本地样式表（相对路径或根相对路径）会被读入并内联；本地 `<img>` 会被读取并转成 data URL（总量约 4 MiB、最多 12 张）。
- 页面自带的 `<script>` 一律不执行，`Content-Security-Policy` meta 会被移除，以便注入拖拽脚本。
- 发给 agent 的提示里会带上新顺序、原顺序、每个区块的定位信息（`data-module`、`id` 或首个 class）、以及内联过的样式表路径。

## 已知限制

- 只支持**同一容器内的顶层区块排序**，还不支持跨容器移动、并排分栏、尺寸与对齐调整。
- 顶层区块的判定：`body` 的直接子元素（若 `body` 只有一个包裹元素且该元素有多个子元素，则向内下钻最多两层）；`script`、`style`、`link`、`meta`、`template`、`noscript`、`br` 会被忽略。脚本渲染出来的页面（SPA 空壳）可能得到 0 个区块。
- 容器是横向排列（flex row / 多列）时，改 DOM 顺序未必看得出变化，面板会提示这一点。
- 预览是近似效果：`CSS url()` 引用的图片、`@import`、模块脚本、`srcset` 等不会被解析；页面脚本不会运行；预览按侧栏宽度渲染，没有缩放或设备宽度切换。
- 路径需要手动输入：面板会记住每个会话上次用过的路径，但没有工作区文件浏览。
- 布局意图以用户消息的形式进入会话，因此会出现在对话记录里（这是有意的：你能看到 agent 收到的究竟是什么）。
- 拖拽结果不持久化：刷新页面后需要重新拖动；文件本身不会因为拖拽而改变。
- 每个会话同时只有一个编辑器标签，无法并排比较两个页面。
- 文件变更用 4 秒一次的 `stat` 轮询发现（页面隐藏时降频），不是推送。
